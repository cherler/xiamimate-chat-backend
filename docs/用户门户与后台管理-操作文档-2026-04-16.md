## 二、关键环境变量

在 `.env` 文件中配置（参考 `.env.example`）：

| 变量名 | 用途 | 默认值 |
|--------|------|--------|
| `CHAT_BACKEND_HOST` | 服务监听地址 | `0.0.0.0` |
| `CHAT_BACKEND_PORT` | 服务监听端口 | `8200` |
| `CHAT_BACKEND_SERVICE_SECRET` | 内部服务间调用密钥 | 空（**必须设置**） |
| `CHAT_BACKEND_ADMIN_TOKEN` | 后台管理页面访问令牌 | 空（**必须设置**） |
| `CHAT_BACKEND_PORTAL_TOKEN_TTL` | Portal 令牌有效期（秒） | `1800`（30 分钟） |
| `CHAT_BACKEND_PORTAL_BASE_URL` | Portal 页面基础 URL（用于生成链接，建议填外部可访问地址） | 空（优先回退到 `CHAT_BACKEND_BASE_URL`） |
| `CHAT_BACKEND_SIGNUP_GIFT_POINTS` | 新用户注册赠送积分 | `50` |
| `CHAT_BACKEND_GUEST_DAILY_POINTS` | 游客每日免费额度 | `500` |

```bash
cd /path/to/xiamimate-chat-backend

# 启动
bash scripts/manage_chat_backend.sh start
```

## 四、用户自助门户（Portal）

### 4.1 访问方式

Portal 页面需要短期令牌才能访问，**不支持直接输入网址打开**。

**方式一：用户在聊天中输入 `/me` 命令**

用户在 Open WebUI 中发送 `/me`，系统返回带有 Portal 链接的消息：

```
🔗 **账户门户**
| 功能 | 链接 |
| --- | --- |
| 账户详情 | [打开账户门户查看详细消费记录](http://127.0.0.1:8200/portal?t=<token>) |

👤 **用户信息**
| 字段 | 内容 |
| --- | --- |
| 用户 | xxx |
| 邮箱 | xxx@example.com |
| 套餐 | 免费版 |
| 积分余额 | 450 点 |
| 近30天使用 | 50 次 |

💰 **积分概览**
| 项目 | 数值 |
| --- | --- |
| 当前积分余额 | 450 |
| 累计赠送积分 | 50 |
| 累计购买积分 | 0 |
| 累计消费积分 | 21 |
```

点击链接即可访问门户页面，令牌有效期 30 分钟。

**方式二：通过内部 API 生成令牌**

```bash
curl -X POST http://127.0.0.1:8200/internal/portal/create-token \
  -H "X-Internal-Service-Secret: <your-service-secret>" \
  -H "X-Internal-Service-Name: manual" \
  -H "X-User-Id: <user_id>"
```

返回：

```json
{
  "data": {
    "token": "abc123...",
    "portal_url": "http://127.0.0.1:8200/portal?t=abc123...",
    "ttl_seconds": 1800
  }
}
```

### 4.2 门户页面功能

| 区块 | 说明 |
|------|------|
| 用户信息 | 显示名、邮箱、计划等级徽章 |
| KPI 卡片 | 当前余额、累计获赠、累计购买、累计消耗、30 天事件数 |
| 当前定价 | 各事件类型的单次积分消耗 |
| 消费趋势图 | 30 天日维度柱状图，按事件类型分色，悬停显示详情 |
| 账本明细 | 分页表格（北京时间 `YYYY-MM-DD HH:mm:ss`、类型、积分变动、余额、说明） |

### 4.3 Portal API 端点

| 端点 | 认证方式 | 说明 |
|------|----------|------|
| `GET /portal` | 无（返回 HTML） | SPA 页面，通过 `?t=<token>` 传入令牌 |
| `GET /portal/api/account` | Bearer Token | 账户概览（个人信息 + 积分 + 使用统计 + 定价） |
| `GET /portal/api/ledger?page=1&page_size=30` | Bearer Token | 分页账本明细 |
| `GET /portal/api/usage-daily?days=30` | Bearer Token | 每日聚合使用量（最多 90 天） |

## 五、后台管理（Admin Backoffice）

### 5.1 访问方式

直接浏览器打开：

```
http://127.0.0.1:8200/admin/backoffice
```

页面顶部输入：
- **Admin Token**：对应环境变量 `CHAT_BACKEND_ADMIN_TOKEN` 的值
- **操作者名称**：你的名字/工号（用于审计日志记录）

### 5.2 功能操作

#### 系统概览

进入后台页面后，点击 **刷新概览** 即可看到：
- 总用户数
- 活跃 API Key 数
- 已支付订单数
- 活跃订阅数
- 进行中的分析任务数
- 全平台积分总余额

#### 用户检索

左侧搜索框输入用户 ID、邮箱或显示名的关键词，点击 **搜索**。
也可点击 **最近用户** 查看最近活跃的 20 位用户。

点击用户条目即可查看详细信息：个人信息、积分账户、账本记录、消费事件、支付订单、聊天会话、分析任务。

#### 手动加积分

1. 在左侧 **手动加积分** 区域填写目标用户 ID
2. 填入积分数量（默认 100）
3. 填入原因描述（如 "公测补偿" "Bug 退款"）
4. 点击 **执行加积分**
5. 操作会自动写入审计日志

#### 定价管理

左侧 **定价管理** 区域可查看和编辑各事件类型的单次积分消耗：

- 点击条目展开编辑
- 可修改：显示名、单次积分数、状态（active/disabled）、排序
- 保存后立即生效（缓存自动失效）

#### 审计日志

点击 **刷新审计日志** 查看所有管理员操作记录：
- 操作者、操作类型、目标、请求参数、执行结果、时间
- 支持按目标 ID 过滤

### 5.3 Admin API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/admin/backoffice` | GET | 管理后台 HTML 页面 |
| `/admin/api/overview` | GET | 系统概览指标 |
| `/admin/api/users?query=&limit=20` | GET | 用户搜索 |
| `/admin/api/users/{user_id}` | GET | 用户详情 |
| `/admin/api/users/{user_id}/grant-points` | POST | 手动加积分 |
| `/admin/api/audit-logs?target_id=&limit=50` | GET | 审计日志 |
| `/admin/api/pricing` | GET | 定价列表 |
| `/admin/api/pricing/{event_type}` | PUT | 更新定价 |

Admin API 认证 Header：

```
Authorization: Bearer <CHAT_BACKEND_ADMIN_TOKEN>
X-Admin-Operator: <operator_name>
```

## 六、安全要点

| 项目 | 说明 |
|------|------|
| Portal 令牌 | 短期有效（默认 30 分钟），进程内存储，过期自动清理 |
| Admin 令牌 | 由 `CHAT_BACKEND_ADMIN_TOKEN` 环境变量控制，建议设强密码 |
| 内部服务密钥 | 所有 `/internal/*` 路由需要 `X-Internal-Service-Secret` 头 |
| 审计追踪 | 管理员所有写操作（加积分、改定价等）自动记录在 `app.admin_audit_log` 表 |
| ⚠️ portal token 存储 | 当前存在进程内存中。若需多实例部署，需迁移到 Redis/PG |

## 九、常见问题补充

### 9.1 `CHAT_BACKEND_ADMIN_TOKEN` 怎么生成？

当前没有内置“自动生成后台 token”的 API，做法是**你自己生成一个足够长的随机字符串**，写入 `chat-backend/.env` 的 `CHAT_BACKEND_ADMIN_TOKEN`。

示例：

```bash
openssl rand -hex 32
```

或：

```bash
python3 - <<'PY'
import secrets
print(secrets.token_hex(32))
PY
```

生成后重启 backend：

```bash
bash scripts/manage_chat_backend.sh restart
```

### 9.2 后台管理当前哪些内容可以编辑？

当前 **可以直接编辑/操作**：

- 用户积分：支持后台手动加积分
- 每个行为事件的定价：支持查看和修改 `billing_event_pricing`

当前 **不能直接在后台页面编辑**：

- 套餐定义（`billing_package`，例如月包、点数包）
- 注册送 50 分
- guest 每天 500 分

其中：

- 套餐定义当前来自后端默认配置和数据库 seed，暂时没有 Admin UI
- 注册送 50 分由 `CHAT_BACKEND_SIGNUP_GIFT_POINTS` 控制
- guest 每天 500 分由 `CHAT_BACKEND_GUEST_DAILY_POINTS` 控制

### 9.3 Portal Token 是自动生成吗？页面 URL 属于谁？

是自动生成的，但**不是用户自己生成**，而是由 bridge 或内部服务调用：

- `POST /internal/portal/create-token`

来生成短期 token。

Portal 页面地址属于 **chat-backend**，不是 Open WebUI。

也就是说，用户最终打开的是：

```text
http://127.0.0.1:8200/portal?t=<token>
```

如果配置了 `CHAT_BACKEND_PORTAL_BASE_URL`，则会优先使用这个值生成链接。

`CHAT_BACKEND_PORTAL_BASE_URL` 的配置位置：

- `/path/to/xiamimate-chat-backend/.env`

建议这样配置：

```bash
CHAT_BACKEND_BASE_URL=http://127.0.0.1:8200
CHAT_BACKEND_PORTAL_BASE_URL=http://127.0.0.1:8200
```

当前已调整为以下回退顺序：

1. `CHAT_BACKEND_PORTAL_BASE_URL`
2. `CHAT_BACKEND_BASE_URL`
3. `http://localhost:<CHAT_BACKEND_PORT>`

`/me` 展示层当前也已做以下处理：

- 账户门户链接放在最前面
- 用户信息、积分概览、套餐与计价优先使用 Markdown 表格展示
- 不再显示 `User ID`
- 账本时间统一按北京时间显示，格式为 `YYYY-MM-DD HH:mm:ss`
- 历史英文事件名/说明会在展示层转换成中文标签
- `units` 对用户展示为“总用量（按计费单位统计）`

是否能“自动跟随 Open WebUI 当前打开地址”：

- 目前**不能完全智能判断浏览器地址**
- 原因是 portal link 由 chat-backend / pipeline 在服务端生成，而不是由浏览器前端生成
- Open WebUI 当前页面的 host 并不会传给这段 `/me` 逻辑

所以，如果你希望用户从外部机器访问时也能点开，最稳妥的方式仍然是显式把 `CHAT_BACKEND_PORTAL_BASE_URL` 配成对用户可访问的地址，例如：

```bash
CHAT_BACKEND_PORTAL_BASE_URL=http://你的域名或IP:8200
```

### 9.4 为什么我在 Open WebUI 里输入 `/me` 还是旧回复？

当前代码里 `/me` 已经会：

1. 请求 `/v1/me/account-overview`
2. 再请求 `/internal/portal/create-token`
3. 最后把 portal 链接拼进回复

如果你看到的还是“只有文字摘要，没有 portal 链接”，通常说明是以下几种情况之一：

- Open WebUI / Pipelines 容器没有重启，仍在跑旧进程
- 当前对话没有走 `xiamimate` 这条 pipeline
- portal token 生成分支失败后被降级成纯文本回复

当前仓库已确认：

- `chat-backend` 实际运行端口是 `8200`
- bridge 当前指向的是 `http://host.docker.internal:8200`
- 从 bridge 容器内部直接调用 `/internal/portal/create-token` 是成功的

建议排查顺序：

```bash
cd /path/to/xiamimate-openwebui-bridge
bash scripts/manage_openwebui_bridge.sh restart
bash scripts/manage_openwebui_bridge.sh logs 100
```

然后在 Open WebUI 新开一个对话，再发一次 `/me`。
